## 1. 做什么

把每个 `.pod5` 里全部 read 的 ADC 解成裸小端 `int16`，写成同名 `.dat`。压缩比：

```text
ratio = 原始 int16 字节数 / .pod5 文件字节数
```

这是**整文件**对比（VBZ 信号 + Reads/Run Info + 容器），不是纯 VBZ blob。`max_reads = 0`，全部导出（`full_export=1`）。

跑法：

```bash
export LD_LIBRARY_PATH=~/.conda/envs/pod5-deps/lib:${LD_LIBRARY_PATH:-}
cd build/c++/test
./pod5_unit_tests "[mytest4]"
```

输入路径在用例里为 `../../../test_data/Klebsiella_pneumoniae_KPC2`。文件夹输出目录为 `int16_export_` + 输入文件夹名。

## 4. 结论

1. **整文件大约 2.37:1，空间节省约 58%。** 14 个文件的比非常齐（2.34～2.40），四个 barcode 之间也差不了多少。
2. **read 更长，所以同样 4000 条的文件更大。** 单文件最大约 501 MB（AMtb 满批大约 140～179 MB）。
3. **文件内 read 长短差比 AMtb 更大。** 各文件 per-read CV 约 1.27～1.75（AMtb 约 0.71～0.84），用例打印 `not similar` 指的是同一文件里各条 read 的 int16 大小不齐，压缩比跨文件仍然稳。
4. 切文件仍是 **按 4000 条 read 分批**，末批不足 4000。
5. 与 `docs/DATA_STORAGE_AND_COMPRESSION.md` 第 1.2、2.1 节口径一致。
