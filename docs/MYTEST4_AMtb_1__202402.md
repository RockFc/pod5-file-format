## 1. 做什么

把每个 `.pod5` 里全部 read 的 ADC 解成裸小端 `int16`，写成同名 `.dat`。压缩比：

```text
ratio = 原始 int16 字节数 / .pod5 文件字节数
```

这是**整文件**对比（VBZ 信号 + Reads/Run Info + 容器），不是纯 VBZ blob。`max_reads = 0`，全部导出（`full_export=1`）。

跑法：

```bash
export LD_LIBRARY_PATH=~/.conda/envs/pod5-deps/lib:${LD_LIBRARY_PATH:-}
cd build/c++/test
./pod5_unit_tests "[mytest4]"
```

输入路径在用例里为 `../../../test_data/AMtb_1__202402`。文件夹输出目录为 `/tmp/int16_export_` + 输入文件夹名。

## 3. 结论

1. **整文件大约 2.34:1，不是 4:1。** 47 个文件的比非常齐（2.32～2.38），空间大约省 **57%**。
2. **体积几乎全是信号。** 平均每条 read 约 93 KB 裸 `int16`，对应 `.pod5` 约 40 KB；元数据每行只有几百字节。
3. **单文件内 read 长短差很大。** 各文件 per-read 体积 CV 约 0.71～0.84，`rel_range` 常到 7～10，用例打印 `not similar` 指的是**同一文件里各条 read 的 int16 大小不齐**，不是压缩比不齐。压缩比跨文件反而很稳。
4. 与 `docs/DATA_STORAGE_AND_COMPRESSION.md` 第 1.2、2.1 节口径一致。
